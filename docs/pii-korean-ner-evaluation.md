# 한국어 이름·주소 후보 탐지 평가 (#1266)

> **상태: 평가만 완료, 제품에 포함되지 않음.** 이 문서는 선택적 한국어 개체명 인식(NER)
> 또는 규칙 기반 후보 탐지를 개인정보(PII) 검사에 더할지 판단하기 위한 근거다. 런타임
> 코드, 설정, 의존성은 바뀌지 않았다. 도입 여부는 메인테이너가 결정한다. 현재 정규식
> 스캐너만으로 "한국어 NER을 제공한다"고 말하지 않는다.

## 1. 배경

현재 PII 게이트(`pii.mode`, `stages/silver/pii.py`의 `scan_pii`)는 두 가지만 본다.

- **값 패턴**: 주민등록번호 형태, 휴대전화, 이메일, 사업자등록번호 정규식
- **컬럼명 휴리스틱**: `NM`, `성명`, `주소`, `연락처` 같은 부분 문자열

이름과 주소는 값 패턴이 없다. 컬럼명이 `담당자`, `소재지`처럼 휴리스틱에 걸리지 않으면
이름·주소 값은 검사에 잡히지 않는다. 기획 문서가 말한 "한국어 NER + 규칙 기반 탐지"가
이 공백을 메울 수 있는지, 비용은 얼마인지를 측정했다.

## 2. 넘지 않는 선

이 평가와 이후의 어떤 통합도 다음을 지킨다.

1. **후보는 더하기만 한다.** 게이트의 판정은 `기존 탐지 ∪ 후보 탐지`다. 후보 탐지는 기존
   탐지가 잡은 값을 통과시킬 수 없고, `mode: block`을 무시할 수 없으며, 선언된 PII 컬럼의
   기본 마스킹을 해제할 수 없다. 평가 스크립트는 모든 셀에서 `기존 ⊆ 합집합`을 단언하고,
   단위 테스트도 같은 성질을 확인한다(`tests/unit/test_eval_korean_ner.py`).
2. **원본 값을 밖으로 보내지 않는다.** 측정한 후보는 모두 로컬·오프라인으로 동작한다.
   외부 NER/LLM 서비스로 레코드를 보내는 안은 평가 대상이 아니다(#447과 별개).
3. **원본 값을 기록하지 않는다.** 스크립트는 집계 수치만 출력한다. 테스트가 출력에 셀
   값이 없음을 확인한다.
4. **판정은 참고용이다.** 휴리스틱 결과를 "확인된 PII"로 표시하지 않는다. 모호한 후보는
   사람이 검토한다.

## 3. 합성 코퍼스

`scripts/eval_korean_ner.py`가 시드(기본 1266)로 1만 개 셀을 만든다. 실제 개인정보는
저장소에 없고, 생성 규칙 자체가 실존 값을 피한다.

| 종류 | 생성 방법 | 실존 값이 아닌 이유 |
|---|---|---|
| 주민등록번호 형태 | `YYMMDD-SXXXXXX`, 하이픈 없는 변형 20% | 월이 13~99 — 유효한 날짜가 아니다 |
| 휴대전화 | `010-0XXX-XXXX`, 하이픈 없는 변형, 공백 구분 변형 | 가입자에게 발급되지 않는 0으로 시작하는 국번 |
| 이름 | 성(복성 5%) + 고정 목록의 두 음절 | 어떤 레코드와도 연결되지 않은 조합 |
| 주소 | 시·도(약칭 30%) + 시·군·구 + 흔한 도로명/동명 + 임의 번지, 전각 숫자 10% | 임의 번지, 다른 값과 연결 없음 |
| 자유 텍스트(`비고`) | "담당자 {이름} ({전화})", "{주소} 소재", "{기관} 담당" 등 | 위와 같음 |
| 어려운 음성(hard negative) | 기관·부서(`강남구청`, `민원봉사과`, `신한은행`), 장소(`서울역`, `김포공항`, `서울숲`), 성씨로 시작하는 낱말(`한마음`, `서비스`, `오미자`), 날짜·코드 | 개인정보가 아니다 |

컬럼명은 휴리스틱이 일부 양성을 잡고(`성명`, `주소`, `연락처`) 일부는 놓치며(`담당자`,
`소재지`) 기관명 컬럼 하나(`INST_NM`)는 `NM` 때문에 잘못 잡도록 골랐다. 셀마다 정답
종류(name, address, phone, rrn)를 붙이고, 탐지기가 셀에서 그 종류를 보고했는지로
정밀도(P)와 재현율(R)을 셌다.

## 4. 비교한 후보

| 후보 | 방식 | 설치 |
|---|---|---|
| 기준선(값 패턴) | 게이트의 `VALUE_PATTERNS` 그대로 | 없음 |
| 기준선(값 + 컬럼명) | `scan_pii`와 같은 판정 | 없음 |
| 규칙(정규식 + 사전) | 성씨 사전 + 3음절(복성 4음절) 토큰, 기관·장소 접미사 제외. 주소는 시·도 + 시·군·구 + 도로명/동 + 번지 정규식, NFKC 정규화 | 없음(표준 라이브러리) |
| Kiwi | `kiwipiepy` 형태소 분석: 고유명사(NNP)로 시작하는 어절 중 이름 꼴인 것 | `kiwipiepy==0.24.0` |
| spaCy | `ko_core_news_sm` 3.8.0의 NER: PS → 이름, LC → 주소 | `spacy==3.8.16` + 모델 휠 |
| spaCy PS + 규칙 주소 | 이름은 spaCy PS, 주소는 규칙 | 위 둘 |

Hugging Face의 트랜스포머 기반 한국어 NER(KoELECTRA, KLUE-RoBERTa 등)은 측정하지 않았다.
CPU용 PyTorch만으로 수백 MB이고, 모델마다 학습 데이터와 라이선스를 따로 확인해야 하며,
아래 결과에서 spaCy 소형 모델조차 지연이 기준선의 1000배를 넘는다. 도입을 검토한다면
별도 평가로 다룬다.

### 오탐·미탐의 내용

- **기준선**: 이름·주소 값 패턴이 없어 컬럼명이 휴리스틱에 걸릴 때만 잡는다. `INST_NM`
  컬럼의 기관명 1091건이 `NM` 때문에 이름으로 오탐됐다. 기준선 자체의 미탐도 나왔다:
  공백으로 구분한 휴대전화(`010 0123 4567`)와 하이픈 없는 주민등록번호 형태 13자리는
  값 패턴이 잡지 못한다(컬럼명이 `연락처`면 휴리스틱이 대신 잡는다). 이 부분은 이 이슈의
  범위가 아니어서 후속 이슈(#1296)로 분리했다.
- **규칙**: 오탐은 모두 성씨로 시작하는 3음절 낱말(`한마음`, `서비스`, `오미자`,
  `최우수`, `유기농`, `서울숲`)이다. 미탐은 주로 `원`으로 끝나는 이름(예: `○지원`)이
  기관 접미사 `원`과 겹쳐 빠진 경우다. **주의**: 이 탐지기는 코퍼스를 만든 같은 사전으로
  작성했으므로, 이름·주소 재현율 0.97~1.0은 실제 데이터에서의 성능이 아니라 상한이다.
  실제 공공데이터의 주소 표기(건물명, 층·호, 지번 혼용)와 외국인·개명 이름에서는 더 낮다.
- **Kiwi**: 형태소 분석기가 `김민준`을 `김민`(NNP) + `준`(NNG)처럼 나누는 경우가 많아
  이름 재현율이 0.18에 그쳤다. 개체명 유형이 없어 주소는 판단하지 못한다.
- **spaCy**: 장소명 셀(`서울역`, `한강공원` 등)에서 785건 오탐했고 대부분 LC(장소)를 주소로 읽은 것이다.
  `강남구청`을 PS(사람)로 읽는 등 기관명 오탐도 있다. 이름 재현율은 0.49다. 1만 셀에
  약 28초로, 기준선(25 ms)보다 1000배 이상 느리다.

## 6. 해석

- 어느 후보도 기존 판정을 줄이지 않는다(합집합 규칙). 비용은 **오탐 증가**와 **지연·설치
  크기**로만 나타난다. `mode: block`에서 오탐은 빌드 거부로 이어지므로, 오탐이 많은
  후보를 차단 판정에 바로 넣으면 사용자는 `allow_columns`를 넓히는 쪽으로 대응하게 되고,
  그러면 기존 보호까지 약해질 수 있다.
- 이 코퍼스에서 소형 ML NER(spaCy, Kiwi)은 규칙보다 정밀도도 재현율도 낮았고, 수백 MB
  설치와 1000배 이상의 지연을 요구했다. 합성 데이터라는 한계가 있지만, 짧은 셀 값(이름
  하나, 주소 한 줄)은 문맥이 없어 문장 단위로 학습된 NER에 불리하다는 점은 데이터와 무관하다.
- `ko_core_news_sm`은 CC BY-SA 4.0이다. 모델을 배포 이미지에 넣으면 동일조건변경허락
  조건이 모델 파일 재배포에 걸린다. 도입 시 법무 검토가 필요하다.

## 7. 권고 (결정 아님)

메인테이너가 고를 수 있는 선택지와 이 평가가 지지하는 방향이다.

1. **ML NER 런타임 통합은 보류(no-go)를 권고한다.** 근거: 위 정밀도·재현율, 지연,
   설치 크기, 모델 라이선스. 기본 의존성과 배포 이미지에 넣지 않는다.
2. **규칙 탐지기는 "검토용 후보" 수준에서만 고려할 만하다.** 도입한다면 기본 꺼짐 설정
   뒤에 두고, 결과는 기존 PII 검토 정보에 "휴리스틱 후보"로만 더하며, 먼저 `mode: warn`
   경로의 경고로 시작해 실제 데이터에서 오탐률을 본 뒤 차단 판정에 넣을지 다시 정한다.
   어떤 경우에도 판정은 `기존 ∪ 후보`이고, 켰을 때 거부가 줄지 않음을 테스트로 고정한다.
3. **기준선의 미탐(공백 구분 휴대전화, 하이픈 없는 주민등록번호 형태)은 NER과 무관하게
   고칠 가치가 있다.** 후속 이슈 #1296에서 다룬다.

결정 전까지 상태는 **실험·보류**다. 릴리스 노트와 화면에서 한국어 NER을 제공한다고
표시하지 않는다.

## 8. 재현

기준선과 규칙 탐지기는 프로젝트 환경만으로 실행된다.

```bash
uv run python scripts/eval_korean_ner.py
```

선택 후보는 프로젝트 의존성과 `uv.lock`을 건드리지 않도록 저장소 밖 가상환경에 설치한다.

```bash
uv venv /tmp/ner-eval --python 3.12
VIRTUAL_ENV=/tmp/ner-eval uv pip install -e . spacy==3.8.16 kiwipiepy==0.24.0 \
  "ko_core_news_sm @ https://github.com/explosion/spacy-models/releases/download/ko_core_news_sm-3.8.0/ko_core_news_sm-3.8.0-py3-none-any.whl"
unshare -rn /tmp/ner-eval/bin/python scripts/eval_korean_ner.py --json /tmp/ner-eval.json
```

`unshare -rn`은 네트워크 없이 실행해 오프라인 동작을 확인하는 용도다. 없으면 빼도 된다.
`--show-errors`는 잘못 분류된 합성 값을 출력한다(실제 값이 아니므로 허용).
