# ADR 0001 — 오케스트레이터로서의 Builder

- 상태: 승인됨(Accepted)

> 이 ADR 에는 상태 줄이 없었다. 다른 17개 ADR 은 모두 갖고 있어서, 상태를 훑는
> 사람에게만 비어 보였다. 결정은 저장소 구조 자체로 실현되어 있다 — builder 는
> 데이터 접근을 `kpubdata` 에 맡기고 오케스트레이션만 한다.

## 결정
`kpubdata-builder`를 `kpubdata`의 대체물이 아니라 오케스트레이션 계층으로 취급한다.

## 근거
소스 접근을 `kpubdata`에 유지하면 중복을 피할 수 있고 책임 경계도 명확해진다.
